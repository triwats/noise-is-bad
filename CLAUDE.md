# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

**noise is bad.** is a Grafana panel plugin (`triwats-noiseisbad-panel`, React + TypeScript) for an office television. It answers one question: *how bad are things right now?* The screen gets visually noisier as operational problems increase.

**The name is always `noise is bad.`** — lowercase, with the full stop, everywhere a person reads it: the plugin name in `src/plugin.json`, READMEs, dashboard and panel titles, alt text, docs, comments. Never "Noise Is Bad", never without the period, even at the start of a sentence. Only identifiers are exempt: the plugin id `triwats-noiseisbad-panel`, which must never change, and the embedded font's family label.

Governing rule: **the screen represents available attention, not infrastructure topology.** Healthy things are never shown. All screen space is allocated to things currently deserving attention.

`noise-is-bad-prototype-project-plan.md` is the source of truth for scope, behaviour and ticket sequencing. Read it before starting any ticket. `tasks/todo.md` tracks the ticket in flight.

## Commands

A `Makefile` wraps the setup. `make` on its own lists every target, and `make doctor` reports what is and is not ready locally.

```bash
make setup     # dependencies, playwright chromium, build, and a running Grafana
make dev       # webpack watch build (leave running in its own shell)
make up        # start Grafana and wait for it to report healthy
make down      # stop it
make restart   # required after any src/plugin.json change
make check     # typecheck + lint + unit tests
make e2e       # end-to-end tests; refuses unless Grafana is up
make tv        # open the panel full-screen with no Grafana chrome
make quiet     # open the quiet state full-screen: the DVD logo, bouncing
make spin      # the same, with the 3D text
```

Note on Jest: `d3-hierarchy` and its dependencies ship ES modules only, so the root `jest.config.js` extends the scaffold's `transformIgnorePatterns`. Any future ESM-only dependency needs adding to that list, and the root config is the place to do it, never `.config/`.

Underneath, these are the npm scripts: `dev`, `build`, `typecheck`, `lint`, `lint:fix`, `test`, `test:ci`, `e2e`, `server`.

Single unit test: `npx jest src/NoisePanel.test.tsx` (add `-t "pattern"` for one case).
Single e2e test: `npx playwright test tests/panel.spec.ts -g "pattern"`.

`make setup` brings up three containers: Grafana, a pretend estate of seven services (`demo/exporter`, plain Node, no dependencies, with a control page on port 9101), and Prometheus scraping it every five seconds. `make doctor` reports the state of all of them.

**If Prometheus dies at startup with a bus error, Docker's virtual disk is full.** It memory-maps a file before serving anything, and that fails outright rather than reporting no space. `docker builder prune` is the cheapest fix, because build cache costs only rebuild time. This cost an hour to diagnose once; the symptom looks nothing like the cause.

Six dashboards are provisioned, and **every one of them must carry the panel's full option set**. They are written by hand, so a new option added to `src/types.ts` does not appear in them by itself: the code falls back to its default and the settings look empty in the editor, which reads as the dashboards being out of date. Sweep them whenever an option is added.

`noise is bad. transitions` shows the same scenario in all four appear-and-disappear styles at once, which is the only sensible way to choose between them.

Three of them matter most. **noise is bad.** is the demo: one panel running the `lifecycle` scenario, which walks quiet, one incident, a split, the board breaking up into twenty-odd cells, and recovery, on an 84-second loop. That is the one to put on a television. **noise is bad. states** holds one panel per state and is what most of the e2e suite drives, so `tests/panel.spec.ts` reads `states.json` rather than `dashboard.json`. **noise is bad. real data** runs the same panel against the `demo_service_health` metric in Prometheus, which is the proof the whole chain works. **noise is bad. quiet** (`quiet.json`, `make quiet`) pins the single quiet state so the DVD logo can be watched on its own, indefinitely, without a scenario moving on underneath it.

Anonymous access is enabled, so there is no login.

## Grafana plugin-tools rules

The scaffold is managed by `@grafana/create-plugin`, and `AGENTS.md` points at `.config/AGENTS/instructions.md`. The rules that matter:

- **Never modify anything in `.config/`.** It is regenerated by `npx @grafana/create-plugin update`. Extend webpack, eslint and prettier by importing the `.config` versions in the root config files instead.
- **Never change the plugin `id` or `type`** in `src/plugin.json`.
- Builds must go through the provided webpack config. Do not swap the bundler.
- Training data on the Grafana API is stale. Fetch current docs from grafana.com, which serves plain markdown by appending `.md` to a path. Index: `https://grafana.com/developers/plugin-tools/llms.txt`.

## Architecture (keep these boundaries)

Four layers in a strict pipeline. Only the first knows Grafana exists.

```
Grafana DataFrame
  → Signal Adapter   (Grafana → NoiseSignal[])
  → State Engine     (firstSeen, persistence, hysteresis, severity, pressure → NoiseItem[])
  → Layout Engine    (0 items → quiet, 1 → fullscreen, 2+ → treemap)
  → Renderer         (animation, typography, colour, transitions)
```

The State Engine, Layout Engine and Renderer must not import from `@grafana/*` or depend on Grafana data shapes, so they can be lifted out of the plugin later. `src/adapter/signalAdapter.ts` is the only place that touches `data.series`.

Where things live:

| Path | Role | May import Grafana? |
| --- | --- | --- |
| `src/module.ts` | Plugin registration and panel options | yes |
| `src/types.ts` | Panel options type | yes |
| `src/NoisePanel.tsx` | The panel; currently a placeholder for Epics 4 to 7 | yes |
| `src/grafanaTheme.ts` | Maps `GrafanaTheme2` onto `NoiseTheme` | yes |
| `src/adapter/` | The Signal Adapter: frames in, `NoiseSignal[]` out | yes, and only here |
| `src/noise/` | The domain contract from Epic 2 | **no** |
| `src/demo/` | Scenario generator and its clock (Epic 3) | **no** |
| `src/render/` | Quiet mode, bounce and spin physics, single incident, treemap | **no** |

`src/architecture.test.ts` enforces this: it fails if anything under `src/noise/`, `src/demo/` or `src/render/` imports from `@grafana/*`. Add new Grafana-free areas to its list. Renderer components take a `NoiseTheme` instead of calling `useStyles2`, which is what keeps them portable.

### What users are expected to feed it

**The default input is availability: good events over total events, where 1 is perfect and smaller is worse.** That is the ordinary shape of an SLO and what most people already have, so the panel expects it with no configuration: warning below 0.99, critical below 0.95, `lower-is-worse`. Every other shape still works by setting the two levels and the direction.

Be careful changing these defaults. A wrong default is worse than no default, because the failure is silent: thresholds that can never be crossed leave the board quiet through an outage.

**The input is an SLO-shaped number, not an alert.** One number per service plus a warning and a critical level. That covers error budget burned, budget remaining, burn rate and SLI compliance, which is everything people actually have. `docs/metrics.md` is the contract, written for someone arriving from outside, and it is the file to keep honest when any of this changes.

`nameField` matches a **label** as well as a column, which is what makes Sloth and Pyrra work untouched: their recording rules hang labels off the series rather than giving them columns. Setting the name to `sloth_service` means no legend format is needed. The provisioned Sloth dashboard deliberately sets no legend format, so that path stays tested.

Alerts are deliberately not the default: `ALERTS` is always 1 with severity in a label, so there is no magnitude to size a box by, and it turns the panel into an alert list.

**Scoring is continuous, not two buckets** (`scoreOf` in `src/noise/pressure.ts`). A service sitting on the warning level scores 1, one on the critical level scores 3, and it keeps rising at the same rate beyond, capped at 9 so one catastrophe cannot hide everything else. Severity is derived from the score by `severityFromScore`, so the colour and the box size can never disagree.

`direction: 'lower-is-worse'` is handled by negating the value and both levels, after which the ordinary arithmetic works unchanged.

**There is one pair of levels for the whole query, and that is a real limit, not an oversight.** Services held to different objectives cannot both be read correctly by one pair. The answer is a panel per objective group, or a number already normalised against each service's own objective. Reading per-service objectives out of the data would mean guessing which label holds them and over what window, and guessing wrong produces a confidently wrong board. `docs/metrics.md` has the worked numbers.

**The board has a ceiling on boxes** (`src/render/cap.ts`, twenty by default). Past it the worst keep their own box and the rest share one saying how many more. The ceiling counts that box too, so it is a real guarantee. Nothing is ever dropped silently.

### Data contract

```ts
interface NoiseSignal { name: string; severity: number; }   // 0 healthy, 1 warning, 2 critical
interface NoiseItem {
  id: string; name: string; severity: 1 | 2;
  firstSeen: number; lastSeen: number; persistence: number; pressure: number;
}
```

Healthy signals are dropped by the state engine rather than the adapter, so the engine can still tell a recovery from a disappearance.

All of Epic 9's configuration exists (NIB-012, NIB-013): which columns to read, the reduction, warning and critical levels, whether age grows a box, quiet mode and its mark, and the transition time. Defaults match the plan, so an unconfigured panel behaves as the plan describes.

The adapter (NIB-003) is built and deliberately narrow. The first string field names things, the first numeric field says how they are doing. Without a string field the whole frame is one series and its display name carries the labels, which is what a Prometheus query gives. Readings reduce with Last, Max or Mean, then cross thresholds at 1 and 2. When a name arrives from more than one frame the worse reading wins, because this display answers how bad things are. Choosing fields, thresholds and the reduction from panel options is Epic 9, after the prototype gate. Reading SLIs — percentages from PromQL recording rules — is Epic 12, NIB-017 to NIB-022, after that. Three things there will change this file: `severityOf` only knows "at or above", so an availability SLI of 0.5 currently reads as healthy; `0.9995` and `99.95` are the same claim and only `field.config.unit` says which is meant; and a PromQL instant vector is named by its whole label set, which no television can show. The panel will never compute an SLI — recording rules do that, and the panel reads the ratio.

Two traps it already handles, both tested: `Number(null)` is 0, so a gap in the data would otherwise read as healthy, which on a wallboard is the worst possible lie. And a query with no numeric field is reported as unreadable rather than as an empty, healthy estate.

### Behavioural rules the code must honour

- **State persists across Grafana refreshes** (NIB-009). `src/noise/state.ts` is a pure, clock-free reducer: `advance(state, signals, now)` folds one refresh in, `itemsOf(state, now)` reads it back. Persistence and pressure are derived on read, not stored, so they keep rising between refreshes instead of only stepping when data lands.
- **Hysteresis** (NIB-011): a new problem shows immediately; recovery needs `RECOVERY_OBSERVATIONS` consecutive healthy readings, currently 2.
- **A name absent from a refresh is no news, not good news.** A scrape that stopped returning a service is at least as likely to mean the target is down as that it recovered. Absent names are held, not counted toward recovery. The item keeps ageing.
- **Escalation is the same incident continuing.** A warning turning critical keeps its `firstSeen`, so persistence is not reset by a problem getting worse.
- **Demo scenarios advance the engine once a second**, not on every 250ms animation tick. Folding every tick in would make two consecutive healthy observations half a second apart, and hysteresis would damp nothing visible.
- **Pressure** = severityWeight × persistenceWeight. Warning 1, critical 3; persistence <30s 1.0, 30–120s 1.2, 2–5min 1.5, 5+min 2.0. `src/noise/pressure.ts` holds the severity half; `pressureOf` is the seam NIB-010 grows to fold in persistence. Whether persistence should drive area at all, rather than colour, pulse, border or saturation, is an open experiment (Epic 7), so keep that mapping pluggable.
- **Test the wiring, not just the component.** A panel option is useless until it reaches the drawing code, and the treemap is built in exactly one place in `NoisePanel.tsx`. The transition style shipped broken because the component was tested thoroughly and the one line that passes the option was never added. There are now tests in `NoisePanel.test.tsx` under "settings reaching the drawing code" covering that hand-off, and an end-to-end test asserting the four styles differ on screen.
- **Each transition style is a handful of numbers** in `SPECS` at the top of `src/render/transitions.ts`: arrive time, leave time, scale, brightness, easing. Change one value, change how a style feels. Tests assert the styles stay far apart, because two styles that are hard to tell apart on a television are not worth offering.
- **Demo scenarios check the data every 2500ms**, not every animation tick. At one second the wait-before-clearing rule was too weak to stop a service flicking on and off briefly emptying the screen, which is the exact thing it exists to prevent. A real dashboard refreshes every five to thirty seconds, so this is still generous.
- **How boxes appear and disappear is a panel option** (`src/render/transitions.ts`): Grow, Flash, Fade or None, defaulting to Grow. Whether it looks right is a television question, which is why it is a setting rather than a decision in code.
- **Departures are animated, and that matters more than arrivals.** React removes a box the moment its problem clears, so departing tiles are held in state for the length of their animation and drawn where they were while the survivors move in. Before this, a disappearance was the most abrupt event on the board while an arrival was the gentlest, which is backwards for a board about noise.
- **Layout transitions** are built (NIB-008). Tiles are keyed by name, so React keeps the same DOM node for a problem across refreshes and a plain CSS transition on left, top, width and height animates it to its new rectangle. Nothing is torn down and rebuilt, which is what stops the board flashing. Colour is deliberately excluded from the transition: a problem turning critical should register instantly, not fade up. Duration is a panel option defaulting to 500ms.
- **Quiet mode** is built (NIB-004, NIB-005). The physics lives in `src/render/bounce.ts` as a pure `step(state, bounds, dt)` with no clock and no DOM; `QuietMode.tsx` is the thin shell that drives it. It writes `transform` onto a ref rather than re-rendering React sixty times a second, because this runs on a television for days. Bounds live in a ref that resize updates in place, so resizing nudges the mark instead of restarting it. Reflection is folded rather than clamped, so a long frame gap lands the mark where it should be. The mark is a panel option: the DVD logo by default, or the original "noise is bad." wordmark. `src/render/dvdMark.tsx` inlines the logo's path data with `fill="currentColor"` and the seven colours the screensaver cycles, so there is no asset to load and no SVG loader in webpack. `BounceState.bounces` exists for exactly this: the colour changes on contact, and only the pure layer can count walls correctly across a long frame gap, where folding hides several bounces at once. The logo is a trademark of DVD Format/Logo Licensing Corporation. It is kept deliberately and credited, not licensed: the risk that the Grafana catalog review rejects it, or Grafana removes the plugin later, is accepted. Do not remove it or swap the default without asking. **Every third party the package ships is credited in `THIRD_PARTY_NOTICES.md`**, which the root `webpack.config.ts` copies into the package because the scaffold only copies `LICENSE`. Adding a bundled dependency, font or image means adding its notice there; `src/notices.test.ts` fails if the licence texts drift from their sources.
- **The brand** is an 8x8 block of TV static beside "noise / is bad." in Archivo Black, tracked -0.035em at line-height 0.92. `design/brand/generate.py` is the source of truth: from the font and the chosen pattern in `design/patterns.json` it writes `src/render/brandData.ts` (the pattern, the lockup outlined to paths, and the font subset to Latin as an inline WOFF2), `src/img/logo.svg` (the plugin logo: the mark on ink) and `docs/brand/lockup-*.svg` for the README. Never edit those outputs by hand; re-run the script. `src/render/brand.tsx` is the hand-written half.
  - **The fixed lockup is outlined, not typeset.** It then renders identically whether or not a font has loaded, and has a known aspect ratio, so the bouncing marks size themselves without measuring anything — a mark measured before its font arrives bounces off the wrong walls. Only text a viewer types into the 3D mark needs the real font.
  - **The font is embedded, never fetched.** A television on a locked-down office network cannot be relied on to reach Google Fonts. Archivo Black is SIL OFL 1.1; `src/render/fonts/OFL.txt` must travel with it, and a unit test fails if it goes missing.
  - `brand.test.tsx` also fails if `src/img/logo.svg` and `NIB_CELLS` ever disagree, so the plugin list and the panel can never show two different marks.
  - Quiet mark `text` predates the brand and keeps its value so saved dashboards still load; it now draws the lockup. Only the DVD logo cycles colour; an old saved `logo` value from the retired DVD-style option falls back to the calm lockup.
- **The 3D text mark** is the Windows XP *3D Text* screensaver, rebuilt in CSS to a behaviour spec: the lockup, extruded, tumbling forever on a pivot at its centre in a black void. `QuietMode.tsx` is only the choice of screensaver; `BouncingMark.tsx` holds the bouncing one and `ThreeDText.tsx` the 3D one, with `bounce.ts` and `spin.ts` as their pure, clock-free halves. Extrusion is a stack of copies of the lockup between a lit front cap and a lit back cap, inside one `preserve-3d` container, so a frame is one transform however many layers there are. No 3D library, no texture, nothing added to webpack.
  - **Motion is independent constant angular velocities**, `angle += speed × dt` on X, Y and Z, as the spec asks: no easing, no direction changes, no canned cycle. Base speeds 7.3, 12.9 and 4.1°/s have no small-integer ratio, so it never repeats. Per run it re-dices start orientation and each speed within ±20% and direction. It reads as mechanical, not random, which is the point. Do not reintroduce bounded swings or phase-locked axes: that is what made the old Wobble a visible 9-second loop.
  - **Readability is inherently rare, and speeds cannot change that.** Tumbling on three axes, the lockup is readable (facing the room, the right way round, upright within 40°) about 3% of the time, in windows of about 5 seconds, a median of 2 minutes apart. That share depends only on the set of readable orientations, not on the speed ratios; speeds stretch windows and waits together. Measured by simulation over four hours.
  - **Lighting is computed, not painted.** `faceNormal` is exact against the browser's `DOMMatrix`. `shade` is ambient plus Lambert plus Blinn-Phong for metal, with one key light near the line of sight. Sides are lit as the side actually in view — the line of sight with its component along the face removed — so they sit dark behind a bright cap face-on and catch the light edge-on. **Every output is continuous in the angles**; a unit test walks every axis in quarter-degree steps and fails on any jump. The old sphere-map highlight wrapped its angle and leapt across the face twice a cycle.
  - **Walls only repaint when their shade changes.** Lighting reaches layers through custom properties on the rotator, written only when the value changes, with the side shade quantised to 24 levels. Every wall is a GPU texture; per-frame repaints of 48 would cost a television. Measured with GPU compositing: a locked 60fps before and after.
  - **Camera and fit use the bounding sphere**, because any orientation is possible. The camera sits three sphere radii away, so nothing grows past 1.5× as it swings toward the viewer — noticeable, not wide-angle. The largest size whose projected sphere fits 95% of the shorter edge puts the lockup across roughly the middle third to half of a television, and it stays wholly on screen at every angle.
  - **Never put `overflow` other than visible, `opacity` below 1, `filter`, `clip-path`, `mask-image`, `mix-blend-mode` or `contain: paint` on the rotator.** Each silently forces `transform-style: flat`; there is no safe threshold, and afterwards the transform still reads correctly in DevTools while the text renders as a flat sign. Clipping the *stage* is fine — its own transform-style is already flat — and an e2e test measures near against far layers in a real browser, because no unit test can tell the difference.
  - Settings, shown only for 3D text: text, size, depth, speed, material (Metallic or Solid) and colour. Grafana's colour picker stores names like "green", so the panel resolves the colour with `theme.visualization.getColorByName` on the Grafana side before it reaches the renderer.
- **Single incident** is built (NIB-006). `src/render/SingleIncident.tsx` gives one problem the whole panel: the name, the severity word, nothing else. Warning and critical differ by colour, weight and size, not colour alone. `fitFontSize` in `src/render/fitText.ts` approximates the largest size a name still fits at rather than measuring, because measuring means a reflow per frame.
- The treemap is built (NIB-007) on `d3-hierarchy`'s squarified layout. `src/render/treemapLayout.ts` is pure and generic: weighted items and a box in, the same items plus rectangles out. Ordering is deterministic, weight descending then name, so equal-weight tiles never swap places for no reason. Do not write rectangle packing.
- **The panel always paints its own background.** Every state sets `theme.canvas`, except the 3D text, which is always black, so the panel is never see-through. A screen across an office should read as one solid thing, not a widget sitting on whatever Grafana is showing behind it. `src/render/fill.ts` turns a score into a paint strength, shared by the single incident and the treemap so the same problem looks the same in both.
- **A single incident fills the whole panel with its colour**, not just the words. From ten metres you see the colour before you read anything.
- **Cells are filled, not transparent.** A treemap is read by area first and text second. Fill strength tracks pressure, so a problem that has dragged on burns brighter as well as taking more room: that is Epic 7's colour channel and area channel driven from one number. A cell too small for a legible name drops the text and keeps the colour, because twenty unreadable words is noise of the wrong kind while twenty coloured cells is the signal wanted.
- **The demo estate is an online shop of seven services, three of which never break.** A board that only ever shows the whole estate on fire proves nothing. The main story is a blast radius: shipping degrades, then checkout, then the basket, then orders, while search, accounts and reviews stay off the screen entirely. That is what demonstrates the governing rule, and a test asserts the untouched three never appear.

  Two rules for the estate, both learned the hard way. Keep it small: seven reads as a shop, twenty reads as noise for its own sake. And keep every name visually distinct: `shipping-api` next to `shipping-quotes` was unreadable at a glance, which defeats the entire premise.

**Demo steps are written as percent of error budget burned**, not as severities, and turned into signals through the same `scoreOf` the adapter uses. The demo therefore speaks the documented contract rather than a private one, and the two cannot drift apart.

**Stages hold for eight seconds.** Three seconds read as an unexplained total outage; twelve bored the people watching. There is a test asserting no stage is shorter than eight seconds.
- The panel never falls back to Grafana's `PanelDataErrorView`.
- **An unreadable query is not the same claim as a healthy estate.** The panel has three states, not two: nothing readable, nothing unhealthy (quiet mode), and something unhealthy. A wallboard that falls silent because its query broke is worse than one that admits it cannot see. `toSignals` returns a `readable` flag for exactly this.

### Simulator is a first-class feature

Demo mode (Epic 3) feeds `NoiseSignal[]` straight into the State Engine, bypassing the adapter. It is the primary development loop and later part of the public demo.

The generator is built (NIB-002). A scenario is a script of timed steps, each declaring the whole estate's state from that moment on, and `signalsAt(scenario, elapsedMs)` reads the script at a point in time. It owns no clock and no state, so it stays trivially testable and can be driven by a scrubber later. The eight scenarios named in Epic 3 all exist. Pick one with the panel's "Demo scenario" option; `live` uses the query instead.

Still missing from Epic 3: the per-signal severity and age controls. Those want an in-panel control surface, which is better built once there is a real renderer to control.
